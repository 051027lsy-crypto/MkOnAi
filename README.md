# 이너프 (Enough)

예산·구매내역·식사 패턴만으로 **다음 장보기에서 사야 할 것, 미뤄도 되는 것, 예상 지출**을 알려주는 AI 식비 절약 서비스의 웹 대시보드(MVP 시연본)입니다.

재고 관리나 레시피 추천이 아니라 **구매 전 의사결정 지원**에 집중합니다.

---

## 1. 목적과 검증 가설

> "예산·구매내역·식사패턴만으로 다음 장보기를 제안하면 중복구매와 식재료 폐기가 줄어든다"

이 가설 하나를 아래 세 가지로 검증합니다.

| 검증 질문 | 확인하는 지표 |
| --- | --- |
| 영수증 사진·수기 입력 같은 최소 입력만으로 꾸준히 쓰는가 | 재방문율 |
| 추천이 실제 구매 행동을 바꾸는가 | 식비 절감 체감, 추천 이행률 |
| 절감 효과에 돈을 낼 의향이 있는가 | 유료 전환 의향 |

## 2. 타깃 사용자

- 20~35세 자취생·1인가구 직장인, 그중 자취 1~3년차 **자취초년생**
- 1인분 적정량에 대한 감각이 아직 없어 계획 없는 장보기, 중복구매, 폐기가 반복되는 시기
- 초기에는 가계부·핀테크 앱을 이미 쓰는 디지털 지출관리 수용층부터 공략

## 3. 핵심 사용자 시나리오

가설 검증에 꼭 필요한 흐름은 아래 3단계 하나입니다.

1. **설정**: 월 식비 예산, 하루 식사 횟수, 장보기 주기를 한 번 입력한다.
2. **구매내역 입력**: 장을 본 뒤 영수증 사진을 찍거나 직접 입력한다. 식단은 기록하지 않는다.
3. **다음 장보기 추천 확인**: 사야 할 것, 미뤄도 되는 것, 예상 지출을 보고 장을 본다. 이후 리포트에서 추천과 실제 지출을 비교한다.

## 4. 화면 구성

| 화면 | 해시 | 하는 일 |
| --- | --- | --- |
| 다음 장보기 | `#recommend` | 요약(이번 달 식비, 다음 장보기 날짜, 예상 지출, 보류 금액), 사야 할 것 / 미뤄도 되는 것 목록, 예상 영수증. 체크를 바꾸면 합계와 예산 여유가 바로 바뀝니다. |
| 구매내역 | `#purchases` | 영수증 사진 입력(시연), 직접 입력, 입력 중인 영수증, 지난 장보기 기록. 저장하면 추천이 다시 계산됩니다. |
| 리포트 | `#report` | 월 누적 식비 차트, 카테고리별 지출, 직전 장보기의 추천 이행 여부, 중복 구매 감지, 가설 검증 3지표 |
| 설정 | `#setup` | 월 예산, 하루 식사 횟수(1~3끼), 장보기 주기(3·4·5·7·10일) |

## 5. 추천 로직 (규칙 기반 시연)

시연본의 추천은 AI 모델이 아니라 단순한 규칙으로 계산합니다. 실제 서비스에서 AI가 맡을 부분을 화면에서 확인하기 위한 자리입니다.

- **소비 속도**: 품목마다 하루 2끼 기준의 예시 소비일수가 있고, 설정한 식사 횟수에 비례해 줄어듭니다. 예를 들어 우유 1L는 2끼 기준 5일치입니다.
- **재고 소진일**: 구매일부터 소비일수를 더해 계산하고, 재고가 남은 채 또 사면 남은 재고 뒤에 이어 붙입니다.
- **다음 장보기 날짜**: 마지막 구매일 + 장보기 주기 (오늘보다 빠르면 오늘).
- **사야 할 것**: 소진일이 `다음 장보기 날짜 + 장보기 주기`보다 이르면, 그다음 장보기 전에 떨어지므로 이번에 사야 합니다.
- **미뤄도 되는 것**: 그 이후까지 재고가 남는 품목입니다.
- **1회 상한**: `월 예산 × 장보기 주기 ÷ 30`
- **중복 구매**: 재고가 구매 품목 소비일수의 절반을 넘게 남았는데 또 산 경우입니다.
- **추천 이행**: 직전 장보기 날짜를 기준으로 그때의 추천을 다시 계산해, 실제로 산 품목이 추천에 들어 있었는지 비교합니다.
- **재방문**: 최근 4주 중 구매내역을 입력한 주의 비율입니다 (1차 성공 기준 70%).

## 6. 디자인

- 연한 회백색 바탕, 흰 패널, 먹색 버튼, 청록 포인트 하나
- 숫자는 Inter, 한글은 Noto Sans KR, 예상 영수증에만 IBM Plex Mono와 점선·톱니 가장자리 사용
- 라이트·다크 모드와 모바일(하단 탭 내비게이션)을 지원
- 상태는 색 알약으로 표시: 떨어졌어요(빨강), 장보기 전에 떨어져요(주황), 재고 남음(초록)

## 7. 기술 구성

- 하나의 HTML 파일(`index.html`)에 HTML, CSS, JavaScript가 모두 들어 있습니다. 프레임워크와 빌드 과정이 없습니다.
- 화면 전환은 URL 해시(`#recommend` 등)로 처리합니다.
- 외부 의존성은 Google Fonts(Inter, IBM Plex Mono, Noto Sans KR)뿐입니다.

### 실행

브라우저에서 `index.html`을 열면 됩니다. 파일에 `<!doctype html>`이 없으면 맨 위에 아래 두 줄을 추가하세요.

```html
<!doctype html>
<meta charset="utf-8"><meta name="viewport" content="width=device-width, initial-scale=1">
```

## 8. 시연본의 한계

- 모든 품목, 가격, 구매내역, 소비 속도는 **예시 데이터**입니다.
- 영수증 사진은 실제로 읽지 않고, 인식 결과 예시로 품목 3개를 채웁니다.
- 입력한 내용은 저장되지 않아 새로고침하면 처음 상태로 돌아갑니다.
- 품목은 15개로 고정되어 있어 목록에 없는 품목은 입력할 수 없습니다.
- 설문(추천 도움 여부, 유료 의향) 답변은 화면에서만 기록되고 어디에도 전송되지 않습니다.
